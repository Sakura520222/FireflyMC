# FireflyMC 项目知识总结

## 项目概述

FireflyMC 是一个基于 Java 开发的 Minecraft 模组项目，核心功能是为游戏扩展基于 WebSocket 的中继（Relay）和 P2P（点对点）打洞网络通信机制，支持用户在不同网络环境下进行联机。

## 知识分类

### 1. 审查规则 (rules/)

#### 核心审查规则
- **增量审查边界声明**：`quick` 模式下必须明确声明审查边界
- **修复类 PR 回溯规则**：必须扫描同模块其他同类风险点
- **配置边界测试**：配置开关控制的功能必须审查关闭时的流程

#### 专项审查规则
- **线程安全规则**：单线程 executor 禁止内部 join、WebSocket 回调线程安全
- **网络通信规则**：断线重连强制检查、P2P 超时兜底
- **安全规则**：日志脱敏完整性、密码安全专项检查
- **架构规则**：上帝类识别、配置与逻辑分离
- **代码质量规则**：时间单位一致性、魔术值常量化

### 2. 架构文档 (docs/)

#### 整体架构
- **模块划分**：中继模块、P2P 模块、认证模块、管理模块、配置模块、UI 模块
- **技术栈**：Java 21、NeoForge 1.21.1、WebSocket、UDP P2P、Gson
- **线程模型**：虚拟线程 + 主线程委托

#### 核心模块
- **中继模块**：RelayLobbyWebSocketClient、RelayLobbyMessage
- **P2P 模块**：P2PConnectionManager、ReorderBuffer、SendWindow
- **认证模块**：PlayerPasswordManager、密码认证流程
- **管理模块**：ItemCleanupManager、UpdateChecker

#### 架构问题
- **线程安全**：WebSocket 回调、静态状态并发访问
- **网络通信**：断线重连缺失、P2P 握手超时
- **安全问题**：日志脱敏不完整、密码弱哈希
- **架构设计**：上帝类、配置强耦合、UI 代码重复

### 3. 经验教训 (plans/)

#### 审查经验
- **增量审查局限性**：易忽略同模块历史遗留问题
- **配置边界测试缺失**：配置开关关闭时流程卡死
- **安全问题持续关注**：系统级安全问题长期未修复

#### 常见问题模式
- **线程安全问题**：单线程 executor 内部 join、WebSocket 回调线程安全
- **网络通信问题**：断线重连缺失、P2P 握手超时
- **安全问题**：日志脱敏不完整、密码安全问题
- **架构设计问题**：上帝类、配置强耦合、UI 代码重复

#### 技术模式经验
- **定时任务模式**：ScheduledExecutorService + scheduleAtFixedRate
- **线程委托模式**：异步线程 → server.execute() → 主线程
- **日志脱敏模式**：统一脱敏入口覆盖所有日志级别
- **配置开关模式**：0 值表示禁用，>0 表示启用

## 关键发现

### 1. 线程安全是核心问题
- **单线程 executor 内部 join**：导致线程阻塞，退化为同步执行
- **WebSocket 回调线程安全**：回调可能来自不同线程，需同步处理
- **静态状态并发访问**：缺乏生命周期管理，易引发竞态条件

### 2. 网络通信需完善
- **断线重连缺失**：WebSocket 断开后无自动重连机制
- **P2P 握手超时**：无总超时控制，可能导致永久卡死
- **错误处理不完整**：非200状态码静默丢弃，缺乏错误记录

### 3. 安全问题需持续关注
- **日志脱敏不完整**：同一对象的 debug/info 日志使用不同脱敏路径
- **密码安全问题**：使用弱哈希算法和纯数字密码
- **敏感数据泄露**：网络传输、日志输出中的敏感信息未脱敏

### 4. 架构设计需改进
- **上帝类问题**：RelayLobbyMessage 承担过多职责
- **配置强耦合**：直接读取静态配置，难以测试
- **UI 代码重复**：两个 Screen 类 80% 代码相同
