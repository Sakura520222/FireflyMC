## 常见代码问题与审查要点

### 日志脱敏完整性
同一方法内所有日志级别（debug/info/warn/error）的输出必须使用相同的脱敏函数。新增日志时需全局检查同文件的其他日志点，避免分级遗漏。

### 脱敏函数性能审查
高频路径（如心跳 1-30s/次）中调用正则或 JSON 重解析的脱敏函数，需评估性能影响，必要时增加缓存或预编译模式。

### 单线程 executor 禁止内部 join
`SingleThreadExecutor` 中调用 `Future.join()` 会导致线程阻塞退化为同步，应改为异步回调或 `get(timeout)`。

### WebSocket/HTTP 回调线程安全
回调默认来自未知线程，`StringBuilder`/`ByteBuffer` 等累加器必须同步，避免竞态条件。

### P2P 握手超时兜底
所有 `CompletableFuture.join()` 必须配套 `orTimeout()` 或 `get(timeout, unit)`，防止打洞卡死。

### 断线重连强制要求
任何网络长连接（WebSocket、TCP）必须有断线重连机制，缺失为 major 级缺陷。

### 静态可变状态生命周期
多个静态字段跨线程访问时，需提供 reset 方法或使用 `volatile`，明确状态重置时机。

## 近期审查模式总结

- **增量审查盲区**：`quick` 模式仅聚焦增量修改，易忽略同模块历史遗留问题。
- **修复类 PR 的隧道视野**：审查者易只验证当前修复，未扫描该模块其他同类风险点。
- **配置边界测试缺失**：配置开关控制的功能必须审查关闭时的流程完整性。
- **静态状态生命周期管理**：多个静态字段跨线程访问时需提供 reset 方法。
- **密码安全专项审查**：认证模块需强制检查密码传输与哈希算法。

## 经验教训

- **增量审查局限性**：多轮小修复可能掩盖底层设计问题，需定期全量健康度评估。
- **脱敏正则范围审查**：宽匹配可能误杀非敏感信息，需权衡安全与可用性。
- **配置开关边界测试**：类似 `playerAuthEnabled` 的配置，必须强制审查"关闭时"的行为，避免流程卡死。
- **密码安全持续关注**：系统级安全问题可能因长期未修复而被忽视，需在每次相关模块审查时重新评估。
- **审查模板强制要求**：在 PR 模板中增加"是否波及同模块历史问题"检查项，强制审查者声明边界。
