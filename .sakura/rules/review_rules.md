# 代码审查规则

## 审查质量要求

### 覆盖度规则
- **增量审查边界声明**：`quick` 模式下必须明确声明审查边界，提示扫描同模块历史问题
- **修复类 PR 回溯规则**：修复类 PR 必须快速扫描该模块的其他同类风险点
- **配置边界测试**：任何由配置开关控制的功能，必须审查配置关闭时的流程完整性

### 准确度规则
- **严重程度标记标准**：
  - 🔴 Critical：功能完全不可用、数据丢失、安全漏洞
  - 🟠 Major：核心功能缺陷、线程安全问题、资源泄漏
  - 🟡 Minor：代码质量问题、性能优化、可维护性
  - 💡 Suggestion：优化建议、代码整洁度

### 完整性规则
- **上下文理解**：审查必须理解 PR 的完整意图和项目背景
- **历史问题关联**：审查需结合项目记忆中的已知问题进行交叉验证

## 专项审查规则

### 线程安全规则
| 规则 ID | 规则名称 | 说明 |
|---------|----------|------|
| THD-01 | 单线程 executor 禁止内部 join | `SingleThreadExecutor` 中调用 `Future.join()` 会导致线程阻塞，应改为异步回调 |
| THD-02 | WebSocket/HTTP 回调线程安全 | WebSocket/HTTP 回调可能被不同线程调用，累加器必须线程安全 |
| THD-03 | 静态可变状态需明确生命周期 | 多个静态字段跨线程访问时，必须提供 reset 方法或使用 volatile |
| THD-04 | 虚拟线程并发安全 | 使用虚拟线程时，静态标志需使用 AtomicBoolean 替代 volatile |

### 网络通信规则
| 规则 ID | 规则名称 | 说明 |
|---------|----------|------|
| NET-01 | 断线重连强制检查 | 任何网络长连接（WebSocket、TCP）必须有断线重连机制 |
| NET-02 | P2P 超时兜底 | 所有 `CompletableFuture.join()` 必须配套 `orTimeout()` 或 `get(timeout, unit)` |
| NET-03 | HttpClient 实例复用 | 每次 `ensureConnected` 创建新 HttpClient 会产生大量临时对象 |
| NET-04 | 网络请求错误记录 | 所有网络请求必须记录具体错误码和消息，避免静默丢弃 |

### 安全规则
| 规则 ID | 规则名称 | 说明 |
|---------|----------|------|
| SEC-01 | 日志中禁止输出 token/secret | 审查所有 `logger.debug/info` 调用，确保敏感字段被脱敏 |
| SEC-02 | 日志脱敏完整性校验 | 同一方法内所有日志级别必须使用相同的脱敏函数 |
| SEC-03 | 密码安全专项检查 | 认证模块需检查哈希算法、密码复杂度、传输加密 |
| SEC-04 | 脱敏函数性能审查 | 高频路径的脱敏操作需评估复杂度，必要时增加缓存 |

### 架构规则
| 规则 ID | 规则名称 | 说明 |
|---------|----------|------|
| ARC-01 | 上帝类识别 | 承担过多职责的类需拆分，违反单一职责原则 |
| ARC-02 | 配置与逻辑分离 | 配置项应与业务逻辑分离，支持热更新 |
| ARC-03 | 静态状态管理 | 静态可变状态必须提供 reset 方法或使用 volatile |
| ARC-04 | UI 代码强制抽取 | 超过 10 行的绘制代码出现在第二个 Screen 时即应抽象 |

### 代码质量规则
| 规则 ID | 规则名称 | 说明 |
|---------|----------|------|
| COD-01 | 时间单位一致性 | 同一方法/功能块内的 TimeUnit 必须统一 |
| COD-02 | 魔术值常量化 | 所有魔术值必须定义为常量并添加文档注释 |
| COD-03 | 变量命名与单位匹配 | 变量名含 `Seconds` 却使用 `TimeUnit.MINUTES` 需注释说明 |
| COD-04 | 字符串操作性能评估 | 高频路径的字符串操作需评估 GC 压力 |

## 项目特有规范

### Minecraft Mod 开发规范
- **Registry 注册体系**：新增游戏内容必须遵循 Registry 注册体系
- **Access Transformers**：修改原版访问权限统一使用 Access Transformers (AT)
- **NBT 数据存储**：动态数据存储统一使用 NBT 格式
- **Bukkit 消息发送**：必须走 `server.execute()` 确保主线程

### FireflyMC 特有规范
- **日志脱敏统一入口**：所有日志输出的 JSON 必须经过 `sanitizeRelayJsonForLog()`
- **配置开关模式**：0 = 禁用，>0 = 启用并作为参数值
- **线程委托模式**：异步线程 → `server.execute()` → 主线程执行
- **资源清理模式**：任务取消后必须置 null 并记录日志

## 审查流程建议

### 快速审查清单
1. **功能完整性**：PR 描述的功能点是否都在代码中实现
2. **线程安全**：检查 executor、WebSocket 回调、静态状态
3. **网络通信**：检查断线重连、超时控制、错误处理
4. **安全问题**：检查日志脱敏、密码安全、敏感数据传输
5. **配置边界**：检查配置开关关闭时的流程完整性

### 深度审查清单
1. **架构设计**：检查上帝类、分层混乱、配置耦合
2. **性能影响**：评估高频路径的性能开销
3. **历史问题关联**：检查是否波及同模块已知风险
4. **测试覆盖**：检查边界条件、异常处理
5. **文档完整性**：检查注释、常量定义、接口语义
