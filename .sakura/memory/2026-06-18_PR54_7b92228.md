# 代码审查深度反思

## 1. 审查质量评估

### 覆盖度：存在明显盲区

**遗漏的关键问题**：

1. **WebSocket 保持连接的生命周期不完整**：`ClientEventNotificationEvents` 新增"关机维护期间保持 WebSocket"逻辑，但审查仅关注了 `serverShutdown` 的线程安全，未追问：
   - 保持连接的超时上限是多少？无限期保持是否会导致资源泄漏？
   - 玩家退出游戏时，这个"保持的连接"最终由谁关闭？
   - 服务端认为玩家已离线，客户端连接还在，消息处理是否会有异常？

2. **聊天去重逻辑的边界未审查**：35行新增代码中，去重实现的具体方式（时间窗口？HashMap？）是否有内存泄漏风险？高消息频率下性能如何？

3. **TitleWorldRenderer 渲染正确性未验证**：只提了性能问题，未检查：
   - 矩阵栈（PoseStack）状态是否正确压栈/出栈
   - 字体渲染是否有资源管理问题
   - 与 `HUDRenderer` 是否存在渲染顺序冲突

### 准确度：标记合理

- `major` 标记准确，项目记忆明确要求"静态布尔标志优先使用 `AtomicBoolean`"
- `minor` 和 `suggestion` 严重程度判定合理

### 完整性：对架构迁移意图理解不足

从 Mixin 注入迁移到 `RenderLevelStageEvent` 是重要的架构改进，但审查未验证：
- 原有功能是否 100% 覆盖（隐身效果兼容性只是提及，未验证）
- 迁移前后的渲染行为是否一致（如渲染层级、遮挡关系）

## 2. 发现的模式

### 代码模式
- **渐进式解耦**：项目正从 Mixin 注入转向事件驱动，这是正确的方向
- **静态状态管理持续薄弱**：`serverShutdown` 问题与历史问题模式一致
- **版本号管理执行不到位**：规范存在但未被开发者遵守

### 架构观察
- WebSocket 生命周期复杂度持续增长：从"连接-使用-断开"变为"连接-使用-保持-重连-最终断开"
- 渲染管线从实体级注入提升到世界级事件，失去了引擎原生的视锥体剔除

## 3. 规范完善建议

### 新增规则

| 规则 | 说明 |
|------|------|
| 世界空间渲染器强制裁剪 | 使用 `RenderLevelStageEvent` 的渲染器必须实现距离裁剪，禁止无限制遍历实体集合 |
| WebSocket 非正常保持需完整生命周期 | 登出/断线后保持连接必须声明：超时上限、最终清理触发条件、心跳策略 |
| 架构迁移验证清单 | 移除 Mixin/重构核心路径时，必须逐项对比原实现的功能点覆盖 |

| 原规则 | 强化方向 |
|------|------|
| 版本号禁止硬编码 | 建议引入编译期检查或 CI 脚本，而非仅靠人工审查 |
| 静态状态必须可重置 | 本次 `serverShutdown` 缺少 reset 调用点审查，应补充"在 closeHandler 链末端调用 reset"的验证 |

## 4. 经验教训

### 值得关注的要点

1. **渲染架构迁移的隐性代价**：从 `EntityRenderer.render()` 注入迁移到世界事件，虽然解耦了，但**失去了引擎原生的视锥体剔除**。未来类似迁移必须将"重新实现裁剪"作为阻塞级验收项。

2. **WebSocket 复用的边界膨胀**：每次扩展 WebSocket 用途（消息通知→维护保持→聊天去重），生命周期管理复杂度指数增长。审查时应要求开发者提供状态机图或生命周期说明。

3. **全量审查的注意力陷阱**：大改动（+114/-89）容易吸引全部注意力，小改动（+35行）中的逻辑隐患反而被忽略。应强制对每个变更文件输出至少一条审查意见。

### 对特定技术的审查经验

- **`RenderLevelStageEvent` 使用模式**：这是 Fabric 的世界渲染扩展点，审查时应检查：Stage 选择是否正确（AFTER_SOLID_BLOCKS vs AFTER_TRANSLUCENT_BLOCKS）、是否正确处理局部坐标转换
- **跨线程布尔标志**：Java 中 plain boolean 的跨线程可见性问题是延迟的（可能几毫秒到几秒才同步），在"关机维护"这类需要即时响应的场景下，必须用 `AtomicBoolean` 或 `volatile`
