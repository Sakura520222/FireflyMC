**三、规范完善建议**

1. **新增/修改审查规则**  
   - **规则 A：迁移/清理路径必须提供可注入的测试点**  
     *要求*：对所有涉及文件删除、迁移的关键路径（如 `MusicCache.ensureInitialized`）提供 **包私有/受保护** 方法或可覆写的钩子，以便单元测试模拟 `hasLegacyCacheLeft` 为 true/false、模拟 `IOException`。  
   - **规则 B：异常判定统一使用业务维度**  
     *要求*：在解码路径中，所有异常（`BitstreamException`、`RuntimeException`、`IOException`）的后续处理必须先依据 **字节完整性**（`expectedBytes`、`bytesRead`）做统一判断，再决定 `RETRY` / `DECODE_FAILED`，禁止仅凭异常类型分支。  
   - **规则 C：HttpClient 重定向安全**  
     *要求*：所有 `HttpClient` 实例在创建时显式设置 `Redirect.NEVER`，或在 `openFollowing` 完成后校验最终 URI scheme 必须为 **https**，并在审查时检查对应常量/注释。  
   - **规则 D：阈值统一声明**  
     *要求*：项目中出现的时间/大小阈值必须统一在 `Constants` 或 `Config` 中声明，避免同文件出现硬编码与常量并存的情况。  

2. **项目特有规范要点**  
   - **缓存迁移日志**：在 `MusicCache` 的迁移路径（包括 fail‑closed）中，**每一次删除失败** 必须记录 `log.warn("wipeLegacyCache failed: {}", e.getMessage(), e)`，并在日志中标记 `cacheId`、`path`，便于运维定位残留文件。  
   - **异常日志脱敏**：所有捕获的异常若包含用户音频文件路径、URL 等信息，必须统一通过 `LogSanitizer.sanitizePath()` 进行脱敏后输出。  
   - **单元测试覆盖率门槛**：对 **可靠性关键路径**（缓存迁移、网络 206 防御、异常分类）要求 **100% 分支覆盖**，并在 CI 中强制 `jacoco` 报告不低于 **90%**（针对 `MusicCache`、`MusicPlayer`）。

**四、经验教训**

### 总结

本次审查整体把握住了 PR 的核心风险，并给出了切实可行的改进建议。要进一步提升审查质量，建议：

1. **在增量审查前加入“历史债务扫描”**，快速定位涉及的公共类（如 `HttpClient`）是否仍携带旧风险。  
2. **把可靠性关键路径的单元测试列为必备**，审查时直接检查是否提供对应的测试类或可注入点。  
3. **统一异常处理与阈值声明**，通过工具类或配置中心降低代码分散带来的维护成本。  

通过上述措施，可在保持快速审查效率的同时，进一步降低遗漏风险，提升代码库的安全与可靠性。
