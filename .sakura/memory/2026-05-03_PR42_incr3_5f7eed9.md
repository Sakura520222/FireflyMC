### 4. 经验教训

**值得未来关注的要点**
- **debug 日志的“隐形风险”**：开发常忽略 debug 级别日志泄露，生产环境意外开启 debug 可能暴露敏感信息。
- **修复类 PR 的“隧道视野”**：审查者易只关注当前变更是否修复问题，而忽略该模块其他潜伏问题。
- **高频调用路径的日志开销**：heartbeat 通常 1-30s/次，脱敏操作若重（如完整 JSON 遍历）可能影响性能，需在审查时评估复杂度。

**对特定技术的审查经验**
- **WebSocket 日志脱敏**：需区分控制消息（heartbeat/stream）与数据消息，前者频率高但结构固定，可预编译脱敏模式。
- **增量审查的“补丁叠加效应”**：连续多轮小修复可能掩盖底层设计问题（如本项目的线程安全依然未解决）。
