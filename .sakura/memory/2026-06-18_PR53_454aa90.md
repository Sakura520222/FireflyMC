# 审查反思报告

## 1. 审查质量评估

### 覆盖度：存在明显盲区

**遗漏的关键问题：**

1. **跨级聊天功能完全未被审查**：摘要提及"QQ群与MC聊天双向互通"，但审查结果中无任何评论。这是高风险功能，应审查：
   - 消息长度限制（防止内存轰炸）
   - 发送频率限制（防止刷屏）
   - 敏感词/命令注入过滤（MC聊天可能执行命令）
   - 权限边界（谁可触发、谁可见）

2. **ServerShutdownManager 安全边界缺失**：仅表扬了注释，未审查：
   - 云端关机指令是否有认证机制（防伪造）
   - 指令是否有有效期/防重放
   - 客户端离线后收到的关机指令如何处理

3. **P2PConnectionManager 并发安全**：仅指出了 `addCandidate` 性能问题，未审查候选地址列表在多线程添加/读取时是否需要同步。

4. **FIN 包处理逻辑**：摘要提及但无具体审查，FIN 包丢失时的超时清理机制是否完善？

### 准确度：基本合理，一处可商榷

- `volatile` 标记 major ✅ 准确，典型的并发可见性bug
- 单线程 executor 内 `join()` 标记 major ✅ 准确，符合 THD-01 规则
- `Thread.sleep` 轮询标记 minor ⚠️ **偏轻**：在 P2P 高频场景下，5ms 轮询 5 秒 = 1000 次无效唤醒，建议提升为 minor-high 或在评论中强调生产环境影响
- ULA 地址未过滤标记 minor ✅ 准确

### 完整性：理解到位但执行不均

审查者准确理解了：
- IPv6 双栈 + fallback 设计意图
- 背压机制解决什么问题
- 幽灵世界根因及修复逻辑
- 为什么避开 `Minecraft.disconnect()`

但对"新功能 = 新风险"的意识不足，跨级聊天这种涉及外部系统交互的功能应触发安全审查思维。

## 2. 发现的模式

### 代码模式
| 模式 | 表现 | 风险等级 |
|------|------|----------|
| 跨线程状态共享 | `ClientState.serverShutdown` 无 volatile | 高 |
| 异步转同步 | `CompletableFuture.join()` 滥用 | 高 |
| 轮询等待 | `Thread.sleep(5)` 替代条件变量 | 中 |
| 线性扫描 | 小集合用 `stream().anyMatch()` | 低 |

### 架构观察
1. **P2P 层持续演进**：从基础打洞 → 多候选地址 → 背压 → FIN 处理 → 资源级联清理，架构逐步成熟
2. **事件驱动成熟**：`ClientEventNotificationEvents` 扩展了关机状态，事件机制复用良好
3. **Mixin 使用克制**：仅在 `ConnectScreen` 注入，且有详细注释说明为什么不直接调用原方法

## 3. 规范完善建议

### 新增规则

| 规则 ID | 规则名称 | 说明 |
|---------|----------|------|
| SEC-01 | 外部系统交互安全审查 | 聊天互通、WebHook 等涉及外部系统的功能，必须审查：消息长度限制、频率限制、注入过滤、权限控制 |
| SEC-02 | 远程指令认证强制 | 云端下推的指令必须审查认证机制、有效期、防重放 |
| PERF-01 | 禁止 sleep 轮询等待 | 禁止用 `Thread.sleep` 做条件等待，改用 `CountDownLatch`/`Condition`/回调 |
| NET-01 | IPv6 地址分类强制 | 公网通信必须过滤 ULA(fc00::/7)、LBA(fe80::/10)、loopback |

### 修改现有规则

| 原规则 | 修改建议 |
|--------|----------|
| 单线程 executor 禁止 join | 扩展为：**任何 executor 内禁止无超时的阻塞调用**（包括 join、get、sleep） |
| P2P 超时强制兜底 | 扩展为：**所有 CompletableFuture.join() 必须配套 orTimeout()**，不限于 P2P 模块 |

## 4. 经验教训

### 核心教训

**「功能摘要 ≠ 审查完成」**：PR 摘要列出的功能点应逐项核对是否都有对应审查评论。本次"跨级聊天"出现在摘要但零审查，是典型遗漏。

### 技术要点沉淀

1. **IPv6 地址分类是易错点**：开发容易只过滤 link-local/loopback，遗漏 ULA。审查时应携带地址分类表：
   - GUA (2000::/3) ✅ 可用于公网
   - ULA (fc00::/7) ❌ 不可路由
   - LBA (fe80::/10) ❌ 仅链路本地

2. **远程指令系统是攻击面**：`ServerShutdownManager` 允许服务端控制客户端行为，这类"控制面"功能的安全审查优先级应高于"数据面"功能。

3. **大版本 PR 需要模块化 checklist**：+829 行变更涵盖 5 个独立功能，应按模块分别审查，避免顾此失彼。
