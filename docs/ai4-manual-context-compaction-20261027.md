# 工作台上下文占用与手动压缩

对应设计 3.5.2、3.5.3 和第 9 节的工作台体验要求。本批实现已交主代理统一构建，本文不提前声明图形或完整交付验收通过。

## 可用入口和显示范围

- 工作台「资料 → 上下文」展示中文预算、历史投影的本地保守估算、上次模型输入组装的完整估算、摘要时间/版本/来源范围和当前摘要。历史估算明确不含系统策略、工具定义及任务状态前缀；上次完整估算包含消息及当时的工具定义/请求封套，只说明历史请求，不冒充下一次请求的准确值或供应商计费 Token。
- `AiServerService` 向运行时和工作台复用同一 `ContextCompactor`。最近组装统计只含计数、版本、时间及作用域，不缓存原始 prompt、模型请求或密钥。摘要正文经中文渲染分页，元数据中不无界重复发送完整正文；分页正文摘要变化时拒绝拼接旧页。
- 「压缩」使用新协商动作 `CONTEXT_COMPACT`，在原枚举末尾追加、不改变旧动作序号，客户端只在服务器声明该能力时发送；请求另核验 `viewVersion=1` 和精确字段。无命令、控制台、普通聊天或客户端模型调用入口。

## 历史、事务和后台行为

- 手动路径走既有确定性摘要，强制检查可压缩的旧完整轮次，不调用模型、不消耗供应商额度、不创建任务或另一条聊天。完整消息、工具事务、产物和历史引用不删除。
- 任一工具调用事务未闭合时，压缩请求保持等待；跨任务尚未消费的完整问题回答也保留，不能因为手动路径没有 currentTask 而压掉输入。
- 自动和手动压缩的摘要提交同时核验隐私版本、历史语义快照及前一摘要版本；摘要计算不持会话锁，提交竞争会重试，不能覆盖新消息、问题、审批或另一份新摘要。
- `ManualContextRequests` 在同一永久主会话保存请求/终态元数据，按 owner/server/conversation/privacy 绑定。每名玩家同一隐私版本最多一个待处理请求，重复确认不重复追加；重开同工作区能恢复待处理请求，旧隐私版本或其他玩家不能完成它。
- 服务端每 20 Tick 最多把两名玩家交给 IO 线程轮转处理，等待认证或工具结果的请求不会永远占据前两个名额。关闭工作台不取消；重连后仍重新鉴权。结果发送沿已有服务端发送门禁复验当前连接、本人认证和服务器状态，不把旧连接当作新连接的权限。
- 专服/认证/唯一主会话门禁保持；手动摘要不授予施工、物料或审批权限。隐私擦除清理待处理缓存和最近组装统计，已删除隐私版本的排队请求不能写回新历史。

## 代码与验证边界

主要实现：`ContextCompactor`、`ManualContextRequests`、`ContextViewText`，以及 `AiServerService` 的 context 请求/队列/投影、`AiProtocol` 和客户端工作台接线。顶部新按钮继续复用 14px 的文字宽度流式布局，几何用例按 20 个控件更新。

新增行为回归包括：低于自动阈值仍可手动压缩、完整工具轮次等待、跨任务完整答案、历史不变、并发摘要 CAS、预算统计作用域、待处理去重/认证/隐私/重开恢复，以及中文展示与能力协商。主代理统一运行完整构建/JUnit；本子任务未运行 Gradle、完整游戏、图形双客户端或供应商请求。
