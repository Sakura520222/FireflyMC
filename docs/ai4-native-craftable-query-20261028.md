# 原版可合成查询与直接清单交付（2026-10-28）

## 行为

“看一下我当前都能直接做哪些东西”直接调用常驻的 `crafting_discover`。普通合成、烧炼、切石复用原版配方书使用的 `StackedContents.canCraft`；Mod 注册的相同原生配方类也走这条路径。特殊配料、共享物料池及其他现有加工适配器按其实际条件核对。AI 的虚拟 3×3 合成能力保留。

工具一次捕获库存，在服务端内部完成本次配方查询，返回全部匹配项。移除模型可见的 snapshotId/offset/recipeGeneration 翻页参数，以及原来 512 个配方、16 次预检查、12 项结果、256 个物料行和 20000 个目录条目的额外截断。主线程只做分批计算，分批不会成为用户或模型需要续接的操作。

查询持有自己的只读库存观察，不再依赖 60 秒交互游标。切换执行模式不需要重建查询；真正制作时仍使用新的实时计划与实际材料。配方真实重载由查询内部处理一次重试。

完整清单由工具结果直接写入工作台可见消息，与工具结果原子保存。模型取得简洁摘要即可回答，不必为了把表格交给玩家再次逐页读取产物。详细结果仍保存在原记录。工具调用轮次中的“装载工具、继续翻页”等文字不再挤占聊天页，完整事件证据保留。

清除了 HUD、输入框、问题页、布局预览及蓝图页的“结果仅本人可见 / 仅本人可见”固定提示，并调整模型指令，不再重复这些尾句或空的完成清单模板。

## 验证

新增原版 GameTest：原木直接产生木板候选、原料数量匹配、重复查询不消耗库存、虚拟 3×3 仍能匹配箱子。单元测试覆盖首轮直接可用、超长完整表格直接交付、无需产物翻页、过程话术不占历史页。

新增 `dedicated-craftable` 隔离专服验证，用实际 `MaterialInventoryService`、`GameToolBridge` 和 `crafting_discover` 重现原木库存，并使交互快照缓存主动过期；另用一组材料验证超过 12 项的完整结果及查询不扣料。该验证使用本地模拟连接，不调用模型。

最终构建通过：1116 项单元测试、76 项必需 GameTest 全部通过。隔离专服中 1290 条配方目录一次查询完毕；6 个橡木原木、7 个白桦原木的场景返回 5 项，另一组材料返回 106 项。两次均强制令交互快照游标过期，查询仍完整结束，库存未消耗，未建立执行操作。中文结果包含“橡木木板”“白桦木板”。详细结果随 JAR 交付。

本轮专服调用耗时约 2.22 秒和 1.21 秒，只是本机隔离验证样本，不含模型或网络往返，也不代表整合包长期性能。未在用户生产专服与真实图形客户端上复测；无提交、推送、发布或自动替换实装文件。
