# FireflyMC AI 4.0 P0 实施记录

日期：2026-10-20。工作分支：`3.1.0`。本记录描述当前未提交的源码实现，不代表已发布或已部署。

产品规则以 [重构设计](FireflyMC-AI-4.0-重构设计.md) 为准，第三方联动证据以 [模组联动清单](FireflyMC-AI-4.0-模组联动清单.md) 为准。本轮重读了工作区、压缩、执行器、权限、迁移和第 9 节 P0 要求；没有修改这两份已暂存的设计文档。

**本会话最新明确修订优先：伙伴默认名改为“小萤”；点歌保留 `/点歌` 别名。** AI 仍只使用 `/fireflymc ai ...`，不恢复独立 AI 根命令。请设计会话同步这一点歌例外。

## 1. P0 实际实现

| 领域 | 实际行为 | 主要代码 |
|---|---|---|
| 唯一工作区 | 世界持久 `serverInstanceId` + 玩家 UUID；控制台独立命名空间；稳定的 `primaryConversationId`，任务不新建聊天 | `ai/workspace/WorkspaceManager.java` |
| 完整历史 | 带 seq、messageId、taskId、时间及工具事务 ID 的追加日志；消息与检查点按批次提交；同步强制落盘、校验和、revision 乐观并发检查 | `ai/conversation/ConversationStore.java` |
| 持久恢复 | 世界写入锁、元数据原子替换；不完整日志尾部先保存再修复，已提交日志损坏则拒绝加载；不静默建立替代会话 | `ai/storage/AiJson.java`、`WorkspaceManager` |
| 上下文压缩 | `W - O - T - S` 预算，默认 75% 阈值；按完整任务轮次与工具事务切分，保留所有未完成任务和审批状态；模型摘要失败回退有来源的摘录索引 | `ai/context/ContextCompactor.java` |
| 摘要一致性 | 保存来源范围、摘要版本、模型、时间、摘要源 digest；仅允许合并 Token/耗时记账变化，消息/任务/审批变化须重取快照 | `ContextCompactor` |
| 检索与产物 | `conversation_search`、`conversation_read`、`task_lookup`、`artifact_read`、`memory_lookup`；工具只访问当前绑定工作区；超长结果保存全文并返回产物引用 | `ai/tools/WorkspaceTools.java` |
| 任务运行时 | 多轮模型—工具循环，完整回填每条接受的调用；未知工具、无效参数、禁用、拒绝、超限均形成结果；终止时有持久最终总结 | `ai/agent/AgentRuntime.java` |
| 调度与预算 | 每工作区串行模型/写入，工作区之间公平轮转；等待批准释放全局工作线程；每玩家最多 8 项未终止任务、全局队列有界；步骤、调用、时间、Token、输出限制 | `ai/task/TaskScheduler.java`、`TaskControl.java` |
| 取消/暂停 | 单任务 cancel/pause/resume/deny；取消传递到 HTTP future 和待执行游戏任务；关闭展示界面没有取消通道；迟到结果不会改写已结束任务 | `AgentRuntime`、`GameToolBridge` |
| 权限 | 验证过的服务端身份，执行前再查权限；普通玩家私有状态仅限本人；OP 不能替代批准；批准绑定所有者、调用 ID、工具和完整参数摘要 | `ai/security/Actor.java`、`ToolPolicyEngine.java` |
| 工具日志 | 执行前持久记录参数摘要、权限、风险、时间；执行后记录完整实际结果、证据和变更；未知结果禁止重放 | `AgentRuntime` |
| 模型接入 | Chat Completions 与 Responses；后者保留 reasoning/加密 reasoning 等关联 output items，使用 call_id 回填；不混用全历史与 previous_response_id | `ai/model/` |
| HTTP 约束 | 每次请求超时、可取消、最多两次瞬态重试、响应体最多 2 MiB、禁止自动重定向；认证/协议错误不盲目重试；不展示原始错误响应和密钥 | `HttpModelGateway.java` |
| 费用记账 | 模型与压缩请求均在发送前持久预留 Token；对重试和缺少 usage 的响应采用保守估算；后续请求/工具不能越过预算 | `AgentRuntime` |
| 命令 | 统一 `/fireflymc ai`，含聊天、任务、状态、工具、审批、取消、暂停恢复、历史、摘要、导出和记忆管理；玩家/控制台共用命令树 | `ai/command/AiCommandTree.java`、`AiServerService.java` |
| 游戏桥 | Minecraft 读取和修改只经服务端主线程；IO 工具使用有界独立线程池；移除原包处理 HEAD 聊天 Mixin，改为已验证的 NeoForge 聊天事件 | `GameToolBridge.java`、`AIChatEventHandler.java` |
| 记忆与锚点 | 独立长期记忆可查看/保存/忘记/清除；清记忆不删除主会话。旧建造锚点按玩家/服务器隔离，并持久到本人工作区 | `ai/memory/MemoryStore.java`、`BuildAnchorManager.java` |

关闭 UI 不取消任务是服务端运行时的独立性保证；本轮没有创建新 UI，不能声称已经实测新工作台的 Esc/HUD 行为。

## 2. 配置与旧能力迁移

- 默认 `ai.engine = "legacy"`，保留既有接入配置与 Chat Completions 的 `max_tokens` 兼容格式。`agent_v2` 为显式启用的协议选择模式，Chat Completions 使用 `max_completion_tokens`，也可配置 Responses。
- 两种配置模式**共用新的隔离、持久化、调度和权限核心**。`legacy` 是兼容接入模式，不会重新启用服务器共享历史或旧权限漏洞。原 `AgenticToolLoop` 等源码保留供迁移对照，已不在命令/事件执行链上。
- `apiUrl`、`apiKey`、`model`、名字、冷却、工具开关/禁用名单等旧键保留；增加协议、上下文、任务预算和并发配置。`maxHistorySize` 不再导致删除历史。
- 默认显示名称、模型伙伴身份、唤醒词和跨服署名使用“小萤”。旧默认“小樱”（含颜色代码）读取时迁移，自定义名称保持；本人 `create` 的名称作用于模型身份和展示，不改写完整历史。
- 模型接入与预算在服务启动时固定，需重启应用新值；AI/工具禁用、身份及权限在执行前重新检查。非法的上下文预留组合会使 AI 初始化明确失败，不猜测巨大窗口。
- 没有导入旧全服共享历史到任何玩家。旧实现的历史在内存中，本轮不存在可安全归属个人的持久历史迁移源。
- AI 的跨服上行仍使用既有 `CrossChatRelayPayload` 和客户端通道。公开 `chat` 输入按配置上行；控制台不向外转发。工作区一旦出现私有任务/内部工具资料，后续完成通知只转发通用提示，详细回答保留本人工作区，避免从长期上下文间接泄露内部结果。
- 普通聊天中的名称唤醒和主动回复间隔仍可触发本人工作区任务；不再把其他玩家的聊天汇入该玩家的模型历史。当前只持久记录进入 AI 的输入/任务，没有继续采集全服公共聊天、全服死亡和全服进度事件。
- `/fireflymc music request|queue|skip|stop` 保持现有行为和权限；按用户最新明确指令保留 `/点歌 <歌名>` 快捷别名，调用同一业务和权限检查。其他模块原有 `/fireflymc` 子树、数据与权限未重构。
- README、点击回复建议及跨服代码注释使用新 AI 命令路径。旧历史设计/计划文件保留为历史资料。

## 3. 恢复策略

1. 已完成任务、完整历史、主会话 ID、记忆和产物在重启后保持。
2. 尚未开始的任务重启后先暂停，重新验证本人连接身份后进入恢复队列。控制台可通过 `resume` 显式恢复。
3. 已开始任务重启后保留检查点并暂停；待审批任务保持待审批，旧批准不跨执行周期直接生效。
4. 工具开始日志存在但没有可信结果时，进入 `RECOVERY_REQUIRED`，补齐明确“不确定”的协议结果，禁止自动重放和普通 `resume`。须核查实际世界后取消旧任务，再发起新任务；P2 将增加具体操作的对账器。
5. 玩家离线后只读任务可继续；需要本人在线状态或写入的阶段暂停，回连重新校验。等待批准/暂停的已开始任务保持该主会话执行顺序，其他任务排队，不交错未完成工具事务。
6. 游戏主线程队列中的任务也会重查取消，关服不等待主线程执行回调，以免主线程等待自身而死锁。

## 6. 带回设计会话的问题与建议

1. **公开跨服聊天与永久私有上下文的边界**：当前采用保守的来源隔离，存在私有任务后只广播完成提示。建议设计显式“分享这条回答”的流程与可公开来源标记，避免仅凭模型措辞判断能否外发。
2. **LAN 访客身份**：既有密码流程主要服务专用服务器，集成服务器访客不一定具备同等验证链。当前未验证访客拒绝 AI 私有工作区访问。建议先确定 LAN 访客可信身份流程，再补专门联机验收。
3. **不确定世界操作的恢复 UI**：P0 不自动重放。建议 P2 为每种副作用注册专门的 verifier，并定义管理员人工核验记录；不可用通用“继续”按钮消除 `RECOVERY_REQUIRED`。
4. **旧被动事件上下文**：当前停止采集全服共享事件，只保留 AI 输入。若需自动记住本人死亡/进度及本人普通聊天，建议明确同意范围和保留策略，以本人观察事件独立记录，避免再次混入其他玩家历史。
5. **迁移默认值**：当前 `legacy` 仅保留接入兼容格式，安全核心统一。建议完成真实提供者与双端验收后再切换默认值，不恢复旧共享历史引擎。

这些问题不改变已确定的唯一工作区、材料守恒、`MATERIALS_ONLY`、AI 统一命令根和点歌别名例外或服务端权威规则。
