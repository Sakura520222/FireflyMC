# 工作台 YOLO、历史与全文展示修复（2026-10-28）

## 用户可见行为

- 聊天页顶部增加 YOLO 开关，单击立即保存到该玩家在本服的工作区，不弹二次确认。开启后工具直接执行，合成、扣料、加工与施工不再逐次要求玩家授权。已经等待批准的任务自动继续。
- YOLO 的当前状态同时传入任务执行检查、游戏线程派发检查和模型指令；蓝图位置候选在 YOLO 下自动完成现场复核与采用，不再要求打开世界预览确认。
- YOLO 下选择物料/原料流体来源或伙伴载体后直接采用，不再弹“确认授权”或“确认选择”二次对话框。
- 手动模式仍可使用；“批准操作”直接显示在聊天页，无需先切换到看板寻找入口。
- 打开聊天保留已加载消息并恢复最新内容。初始页按可见对话计数，工具调用、检查点等内部事件不再挤掉消息。向上滚动到顶部自动读取上一页，并保持原来正在阅读的位置。
- 长消息正文在后台自动续读，全部显示在同一聊天卡片内，正常换行、滚动。移除“更早历史”和“查看全文”读取按钮以及截断后要求点击的提示；不再把读全文操作跳转到资料页。
- 底部输入框从 58 缩为 34 个 GUI 像素，发送/复制按钮缩为 16 像素高、按文字计算宽度；减少间距，保留问题提示及快捷键状态，不与字数计数重叠。

## 根因与实现

旧 OPEN/HISTORY 只读取最后 24 条原始事件，混有工具日志与任务检查点；同时每次打开都清空客户端已同步内容。聊天消息只下发 600 字或有限富组件预览，UI 明确要求再点“查看全文”。审批入口只在看板工具栏。

新增 `ConversationStore.chatPage` 以可见消息分页；原始日志与增量同步保留。完整消息沿用 MESSAGE 分页协议由客户端自动读取，按序列号及消息 ID 组装，重复预览不会覆盖已经补齐的正文。连接更换、隐私删除会清除缓存与未完成的分片，资料页状态保持独立。

`WorkspacePreferences.yoloMode` 默认关闭，原设置文件未包含该字段时亦为关闭。顶部开关使用局部设置更新，不覆盖名称、风格、事件开关或当前未保存的表单。YOLO 不生成逐次人工审批令牌；服务端根据本人的持久化偏好直接执行已有工具，关闭后下次操作恢复手动审批。
